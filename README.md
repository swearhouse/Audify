# Bragi

Bragi is a small, self-hosted web audio player for a trusted home network.
Create playlists in the app by adding YouTube video links; Bragi looks up each
video's title automatically. Use Add Song to choose one or more playlists for
the song. Bragi checks each selected playlist for an existing copy of the
video before adding it. You can also import a YouTube playlist URL to add its
videos automatically. Playlists are private to each user.
Bragi supports play/pause, stop, seeking, previous/next playback, volume, and
searching track titles in the loaded playlist. Videos play in the order listed
in each playlist. Bragi resolves audio streams when you play a track; it does
not download or store audio. Loading another playlist while audio is playing
keeps the current track playing, then continues with the new playlist.

Bragi requires a username and password to use the app and its APIs. It is
intended for a trusted local network, not direct public exposure. The app uses
HTTP by default, so login credentials are not encrypted in transit. Do not
forward its port to the internet; use an HTTPS reverse proxy if you need remote
access.

The player includes experimental Chromecast support in Cast-enabled browsers,
including remote play/pause, stop, seeking, and volume controls. Casting
requires a secure origin (HTTPS, or localhost) and a Chromecast that can reach
and play the resolved audio URL. Some audio streams may not be supported by
the receiver; in that case, playback remains available in the browser.

## User accounts

Bragi stores accounts as plaintext in `users.json`, in its data directory. On
the first login attempt, if the file does not already exist, Bragi creates it
with these initial accounts:

```json
{
  "users": [
    {
      "username": "admin",
      "password": "admin"
    },
    {
      "username": "quest",
      "password": "guest"
    }
  ]
}
```

Sign in with one of these accounts, then edit `users.json` directly on the
server to change passwords or add/remove accounts. Keep the same JSON shape:
each entry needs a non-empty `username` and `password`, and usernames should be
unique. For example, change a password by editing its value, or add another
account by adding an object to the `users` array. Save valid JSON. Changes are
checked against active sessions on each request; removing an account signs
that user out on their next request. Bragi does not provide an in-app user
editor.

Change both initial passwords before sharing access. Anyone who can read the
data directory can read every password in this file. Do not commit `users.json`
to source control or share its contents.

## Data files and persistence

Bragi uses a data directory for account and playlist JSON files:

- `users.json` is created on the first login attempt.
- `user_playlists.json` is created when a user creates their first playlist.
  It stores a separate list for each username. Each playlist has an `id`, a
  `name`, and an ordered `videos` list. Every video has a display `name` and a
  YouTube video `link`. For example:

  ```json
  {
    "admin": [
      {
        "id": "generated-playlist-id",
        "name": "Evening mix",
        "videos": [
          {
            "name": "First song",
            "link": "https://www.youtube.com/watch?v=VIDEO_ID_1"
          },
          {
            "name": "Second song",
            "link": "https://youtu.be/VIDEO_ID_2"
          }
        ]
      }
    ],
    "quest": []
  }
  ```

  Playlist IDs are generated by the app and unique within each user's list.
  Video links must be HTTPS YouTube video URLs. Users can add, import, edit,
  and delete their playlists in the app; adding a song saves it immediately
  to every selected playlist. The JSON file is managed automatically.
  Importing a playlist retrieves its video names and links
  from YouTube and stores them in the user's library. Imports are limited to
  5,000 videos per playlist. Playlists created with the older
  title-and-playlist-URL format must be converted or recreated; back up the
  old file before converting it.

Keep the data directory persistent and writable by the Bragi process or
container. Back it up if you want to preserve accounts and playlists.

## Run locally with Python

Use Python 3.10 or newer. From the project folder:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m audify
```

Open `http://localhost:8000`. The default data directory is `instance` in the
project folder. Accounts are stored in `instance\users.json`, and per-user
playlists are stored in `instance\user_playlists.json`. To use Bragi from
another device on the home network, open `http://<host-LAN-IP>:8000`.

## Run with Docker Compose

Install Docker with Compose support. From the project folder:

```bash
docker compose up -d --build
```

Open `http://<host-LAN-IP>:8000` from a device on the same network. Compose
stores Bragi data in the named `bragi-data` volume. To stop Bragi, run:

```bash
docker compose down
```

## Run on CasaOS

Build Bragi's image on the CasaOS machine from the project source. For example,
over SSH, from a suitable working directory:

```bash
sudo docker build -t bragi:latest https://github.com/swearhouse/Audify.git#main
sudo mkdir -p /DATA/AppData/bragi-data
```

Then in CasaOS **Manual App Install**, use:

- Docker image: `bragi`
- Tag: `latest`
- Web UI: HTTP, port `8000`, path `/`
- Port mapping: host `8000` to container `8000`, TCP
- Volume: `/DATA/AppData/bragi-data` to `/var/lib/bragi`
- Restart policy: `unless-stopped`, if available

After the first login attempt, edit
`/DATA/AppData/bragi-data/users.json` on the CasaOS host to manage accounts.
Playlists are stored in
`/DATA/AppData/bragi-data/user_playlists.json` and can be managed in the app.
The host directory must be writable by Bragi's container user.
